## Развёрнутый вариант

### Контекст

Вся сессия — расследование одного пользовательского вопроса: «форум
№1 в браузере открывается без CSS-оформления». Причина оказалась не
одна, а последовательность из четырёх независимых проблем, каждая
скрывавшая следующую — решались по мере обнаружения фактов (лог
консоли, DevTools Network, содержимое самого CSS-файла).

### 1. Переписывание HTML пропускалось при прерывании Ctrl+C

Диагноз: `rewrite_all_pages()` (подставляет локальные пути вместо
внешних URL в уже скачанных страницах) вызывается ПОСЛЕ того, как
`downloader.run()` для ресурсов полностью завершится. Пользователь
привычно прерывал долгий прогон через Ctrl+C во время скачивания
ресурсов — `KeyboardInterrupt` перехватывался внешним `try/except` и
пропускал вызов `rewrite_all_pages()` целиком. Ресурсы физически
скачивались, но HTML на них не ссылался.

**`run_commands/run_archive.py`, `run_commands/run_forum2x2_archive.py`**
Вызов `downloader.run()` для ресурсов обёрнут в собственный
`try/except KeyboardInterrupt`, который печатает сообщение и НЕ
пробрасывает исключение дальше — выполнение доходит до
`rewrite_all_pages()` в любом случае.

### 2. Укороченный лимит попыток для сторонних (внешних) хостов

Диагноз: мёртвые внешние хосты (картинки, когда-то подгруженные с
других сайтов) использовали тот же лимит попыток, что и сам форум (20,
backoff до 2 часов) — одна мёртвая ссылка могла тянуть retry-цикл
часами/сутками, ничего не блокируя по факту, но захламляя консоль.

**`utils/config.py`**
`RetryConfig.max_attempts_per_task_external: int = 5` — новое поле,
отдельный (более короткий) лимит для задач не с хоста форума.

**`storage/database.py`**
`QueueManager.__init__` принимает `max_attempts_per_task_external`
(по умолчанию совпадает с обычным лимитом — обратная совместимость).
`mark_task_failed` выбирает лимит по тому, совпадает ли хост задачи с
`own_host`.

**`run_commands/run_archive.py`, `run_commands/run_download_test.py`,
`run_commands/run_forum2x2_archive.py`,
`run_commands/run_forum2x2_download_test.py`,
`run_commands/run_scan_test.py`**
Передают новый параметр конструктору `QueueManager`.

### 3. @import/url(...) внутри CSS не обнаруживались (корневая причина отсутствия оформления)

Диагноз (самый глубокий из всех): типичный phpBB `style.css` сам почти
пустой — реальная стилизация подключается через `@import
url("normalize.css")`, `base.css`, `colours.css` и ещё ~9 файлов. Ни
сканер, ни downloader никогда не заглядывали ВНУТРЬ уже скачанного
CSS — видели только `<link rel="stylesheet">` в HTML. Эти ~12 файлов
никогда не попадали в очередь на скачивание вообще, сколько раз ни
перезапускай программу.

**`scanner/css_links.py`** (новый файл)
`extract_css_links()` — находит `@import url(...)` и `url(...)`
(фоновые картинки, `@font-face`) в тексте CSS. `rewrite_css_links()` —
заменяет такие ссылки на локальные пути, когда ресурс уже скачан.
Отдельный модуль (не в `parsers/*` и не в `rewrite_html.py`/
`downloader.py` напрямую) — чтобы не создавать циклический импорт
между `rewrite_html.py` и `downloader.py`, которые оба его используют.

**`scanner/downloader.py`**
Новый метод `_enqueue_css_imports()` — вызывается сразу после
сохранения CSS-ресурса на диск, ставит найденные вложенные ссылки в
очередь (parent_id = сама CSS-задача, для наследования `section_id`).
Работает рекурсивно само по себе, если внутри вложенного файла тоже
окажется `@import`.

**`scanner/rewrite_html.py`**
Новая функция `_rewrite_all_css()`, вызывается из `rewrite_all_pages()`
— переписывает `@import`/`url(...)` внутри каждого скачанного
CSS-файла на локальные пути. В отличие от HTML, у CSS нет отдельной
raw-копии — переписывание идемпотентно по построению (уже переписанная
локальная ссылка не резолвится в известный абсолютный URL повторно).

**`tests/test_css_imports.py`** (новый файл)
Mock-сервер с `style.css`, содержащим `@import` на `normalize.css` и
`colours.css` (второй — с `url(...)` фоновой картинки); проверяет
обнаружение, скачивание, переписывание и идемпотентность повторного
переписывания.

### 4. Доначинка для CSS, скачанного ДО этого патча

Диагноз: патч из раздела 3 (выше) разбирает `@import` только при
СВЕЖЕМ скачивании CSS-файла. Если `style.css` уже был `status='done'`
до переноса патча, он не перекачается сам — его `@import` никогда не
разберётся автоматически.

**`scanner/downloader.py`**
Новый метод `Downloader.backfill_css_imports()` — без единого сетевого
запроса читает уже скачанные CSS-файлы с диска, ищет `@import`, ставит
найденные ссылки в очередь. Идемпотентен — число новых задач считается
по фактическому изменению счётчика строк в `tasks` (не по
`stats.resources_discovered`, который растёт при каждом вызове
`add_task` независимо от того, была ли задача новой).

**`run_commands/backfill_css_imports.py`** (новый файл)
Обслуживающий инструмент, добавлен в главное меню — не разовый скрипт.
Собирает список известных форумов из ОБОИХ реестров сайтов
(`sites_phpbb.json`, `sites_forum2x2.json`) плюс легаси `config.json`,
если тот ещё существует. Не делает сетевых запросов сам; печатает
«нечего проверять», если ни один CSS ещё не скачан — безопасен и для
архивов, начатых уже на исправленной версии.

**`main.py`**
Новый пункт меню, вызывающий `backfill_css_imports`.

**`tests/test_backfill_css_imports.py`** (новый файл)
Проверяет: обнаружение вложенных ссылок у уже `done` CSS-задачи без
единого сетевого вызова (клиент указывает на заведомо недоступный
адрес); новые задачи ставятся как `pending`, не скачиваются сами;
повторный вызов идемпотентен (0 новых задач).

### 5. Молчание консоли при ожидании backoff по отдельному хосту

Диагноз: ожидание общего backoff сервера уже логировало каждые 30
секунд; но путь ожидания backoff ОТДЕЛЬНОГО хоста (сам форум работает,
просто нет свободных задач с других хостов) молчал полностью — при
нескольких хостах, упёршихся в потолок backoff (2 часа), консоль могла
не печатать ничего по несколько минут, выглядело как зависание.

**`scanner/downloader.py`**
Добавлена строка лога на каждую 30-секундную попытку ожидания (тот же
`BACKOFF_WAIT_CHUNK_SECONDS`, что и у общего backoff).

### Проверено на реальном форуме

После переноса всех разделов патча №5 и повторного запуска боевой
архивации форума №1 (phpBB): «Переписывание завершено: 993 страниц,
95906 ссылок заменено на локальные; 7 CSS-файлов, 72 ссылок внутри CSS
заменено» — оформление подтверждено визуально в браузере (потребовалось
жёсткое обновление Ctrl+Shift+R, чтобы сбросить кэш браузера от прежних
просмотров «голой» страницы).
