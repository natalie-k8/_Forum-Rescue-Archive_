# История изменений Forum Rescue Archive

Обновляется после каждого завершённого этапа доработки.

## 2026-08-30 — Оформление форума пропадало из-за @import внутри CSS; переписывание при Ctrl+C; retry для внешних хостов

Расследование одного пользовательского вопроса: «форум №1 в браузере
открывается без CSS». Причина оказалась цепочкой из нескольких
независимых проблем, каждая скрывала следующую. Патчи перенесены в
боевую копию и подтверждены рабочим прогоном на форуме №1.

- **Переписывание HTML пропускалось при прерывании Ctrl+C.**
  `rewrite_all_pages()` (подставляет локальные пути вместо внешних URL)
  вызывается только ПОСЛЕ того, как `downloader.run()` для ресурсов
  полностью завершится. Обычная привычка прерывать долгий прогон через
  Ctrl+C во время скачивания ресурсов приводила к тому, что
  `KeyboardInterrupt` пропускал вызов `rewrite_all_pages()` целиком —
  ресурсы физически скачивались, но HTML на них не ссылался. Исправлено:
  вызов скачивания ресурсов в `run_archive.py`/`run_forum2x2_archive.py`
  обёрнут в собственный `try/except KeyboardInterrupt`, который не
  пробрасывает исключение дальше — переписывание срабатывает в любом
  случае.
- **Укороченный лимит попыток для сторонних (внешних) хостов.** Мёртвые
  внешние хосты (картинки, когда-то подгруженные с других сайтов)
  использовали тот же лимит попыток, что и сам форум (20, backoff до 2
  часов) — одна мёртвая ссылка могла тянуть retry-цикл часами/сутками,
  ничего не блокируя по факту, но захламляя консоль. Добавлено новое
  поле `RetryConfig.max_attempts_per_task_external` (по умолчанию 5) —
  `QueueManager.mark_task_failed` выбирает лимит по тому, совпадает ли
  хост задачи с хостом самого форума.
- **@import/url(...) внутри CSS не обнаруживались — корневая причина
  отсутствия оформления.** Типичный phpBB `style.css` сам почти
  пустой — реальная стилизация подключается через `@import
  url("normalize.css")`, `base.css`, `colours.css` и ещё ~9 файлов. Ни
  сканер, ни downloader никогда не заглядывали ВНУТРЬ уже скачанного
  CSS — видели только `<link rel="stylesheet">` в HTML. Эти ~12 файлов
  никогда не попадали в очередь на скачивание, сколько раз ни
  перезапускай программу. Исправлено: новый модуль `scanner/css_links.py`
  находит `@import`/`url(...)` в тексте CSS; `Downloader` ставит
  найденные ссылки в очередь сразу после скачивания CSS-файла (работает
  рекурсивно); `rewrite_html.py` переписывает такие ссылки внутри самих
  CSS-файлов на локальные пути.
- **Доначинка для CSS, скачанного до этого патча.** Обнаружение @import
  срабатывает только при СВЕЖЕМ скачивании CSS — если `style.css` уже
  был `status='done'` раньше, он не перекачается сам, и его @import
  никогда не разберётся автоматически. Добавлен новый обслуживающий
  инструмент `backfill_css_imports` (пункт меню, не разовый скрипт) —
  без единого сетевого запроса читает уже скачанные CSS-файлы с диска,
  находит вложенные ссылки и доставляет их в очередь; сами файлы
  скачивает следующий обычный запуск архивации. Идемпотентен.
- **Молчание консоли при ожидании backoff по отдельному хосту.**
  Ожидание общего backoff сервера уже логировало каждые 30 секунд, но
  путь ожидания backoff ОТДЕЛЬНОГО хоста (форум работает, просто нет
  свободных задач с других хостов) молчал полностью — при нескольких
  хостах, упёршихся в потолок backoff, консоль могла не печатать ничего
  по несколько минут, выглядело как зависание. Добавлена периодическая
  строка лога на каждую 30-секундную попытку ожидания.
- **Новые тесты:** `tests/test_css_imports.py` (обнаружение, скачивание,
  переписывание и идемпотентность @import внутри CSS, mock-сервер),
  `tests/test_backfill_css_imports.py` (доначинка без сетевых запросов,
  идемпотентность). Вся сюита прогнана без регрессий после каждого
  фикса.
- **Подтверждено на реальном форуме:** после переноса и повторного
  запуска боевой архивации — «7 CSS-файлов, 72 ссылок внутри CSS
  заменено», оформление подтверждено визуально в браузере (потребовалось
  жёсткое обновление Ctrl+Shift+R, чтобы сбросить кэш браузера от
  прежних просмотров «голой» страницы).

## 2026-08-21 — CSS/режимы, три найденных бага реального прогона, выборочная архивация по разделам

Найдено и исправлено при разборе реального боевого прогона форума №1
(phpBB, ~59 000 сообщений). Патчи №1 и №2 ниже уже перенесены в боевую
копию и подтверждены рабочим прогоном; патчи №3 и №4 подготовлены, но
ещё не перенесены на момент этой записи.

- **CSS и остальные ресурсы «пропадали» — оказалось, режим 1 «Спасение
  текста».** Не баг: `ModeConfig` (режим 1/«Спасение текста» vs режим
  2/«Полный архив») определяет `priority_ceiling` — в режиме 1 задачи на
  CSS/картинки/аватары/смайлики (все `priority=2`) создаются в очереди,
  но никогда не скачиваются, пока режим не переключат на 2.
  `rewrite_html.py` не ошибается — просто не находит ресурс в
  `resource_map` и оставляет ссылку непереписанной. Добавлено: новый
  метод `QueueManager.count_deferred_by_mode()`, поле
  `DownloadStats.resources_deferred_by_mode`, явное предупреждение в
  консоли после прогона в режиме 1, если остались отложенные ресурсы;
  новый пункт меню `M` в `main.py` для смены режима с описанием, что
  входит в каждый, плюс текущий режим теперь виден в шапке главного
  меню.
- **`SiteEntry.env_path` — `TypeError` при загрузке `sites_forum2x2.json`.**
  `SiteEntry` требовало поле `env_path`, которое нигде не заполнялось —
  падало при загрузке уже существующего реестра. Исправлено:
  `get_or_create_site` заполняет `env_path`, `load_registry` подставляет
  его из `credentials_path` для старых записей без этого поля.
- **Путаница раздела и темы в пагинации.** `discover_pagination_urls`
  (`parsers/phpbb_parser.py`) искал ссылки с тем же `f=N` для подсчёта
  страниц пагинации СПИСКА ТЕМ раздела, но не отличал их от ссылки на
  конкретную ТЕМУ этого раздела с её последней прочитанной страницей —
  `viewtopic.php?f=9&t=90&start=20` имеет тот же `f=` и `start=`, что и
  `viewforum.php?f=9&start=20`. Сканер листал десятки несуществующих
  страниц раздела вхолостую. Исправлено: дополнительно сверяется имя
  скрипта в пути (`viewforum.php` vs `viewtopic.php`).
- **Превышение лимита длины пути Windows (MAX_PATH, ~260 символов).**
  `FileNotFoundError` при сохранении страниц с глубокой вложенностью
  (раздел/подраздел/тема) — суммарная длина пути легко превышает лимит,
  даже когда каждое отдельное имя папки короткое. Исправлено:
  `scanner/downloader.py` — на Windows абсолютный путь получает префикс
  `\\?\`, снимающий ограничение Win32 API (до ~32000 символов).
- **Разделы верхнего уровня никогда не переоткрывались повторно —
  самый серьёзный найденный баг.** После полного цикла
  сканирование→скачивание→переписывание в архиве оказалась лишь малая
  часть форума (4 раздела, 3 темы при форуме на ~59 000 сообщений).
  Причина: `scanner/scanner.py`, `_bootstrap_root_sections` —
  главная страница форума (со списком разделов верхнего уровня)
  запрашивалась ТОЛЬКО при самом первом запуске, когда таблица
  `sections` была пуста. Если тот первый прогон (тестовый режим с
  лимитом `max_sections`) нашёл лишь часть разделов, все последующие
  безлимитные запуски никогда больше не переоткрывали главную страницу.
  Исправлено: главная страница запрашивается при КАЖДОМ запуске
  `Scanner.run()`; уже известные разделы не трогаются (`INSERT OR
  IGNORE` не сбрасывает `scanned`) — добавляются только реально новые.
  Побочный эффект (осознанный): один дополнительный запрос к главной
  странице на каждый запуск, даже если всё уже отсканировано.
- **Выборочная архивация по разделам (новая возможность).** Форум
  большой, сервер нестабильный, throttle намеренно медленный (надёжность
  важнее скорости) — полный архив может не успеть скачаться. Добавлен
  ДОПОЛНИТЕЛЬНЫЙ режим (не замена «скачать всё»): новая колонка
  `tasks.section_id`, опциональный параметр `allowed_section_ids` в
  `QueueManager.get_next_task()`/`host_backoff_wait_seconds()` и в
  `Downloader.run()`. После сканирования, перед скачиванием —
  пронумерованный список известных разделов с числом тем; ввод номеров
  через запятую или пусто = скачать всё, как раньше. Ресурсы
  (картинки/CSS/...) не имеют своего `section_id` — наследуют раздел от
  родительской текстовой задачи через `parent_id`. Разделы, не выбранные
  сейчас, остаются в очереди нетронутыми для будущего прогона.
- **Новые тесты:** `tests/test_mode_deferral.py`,
  `tests/test_long_paths.py`, `tests/test_selective_download.py`;
  `tests/test_scanner.py` обновлён (resumability-проверка теперь
  ожидает ровно один запрос к главной странице вместо нуля). Вся сюита
  (12 файлов) прогнана без регрессий после каждого фикса.

## 2026-07-25 — Свой логин на каждый форум forum2x2, явный выбор — ограничивать ли сканирование

- **Свой `.env` на каждый форум на forum2x2.** Выяснилось, что на одном
  хостинге разные форумы почти всегда требуют разные логин/пароль — общий
  `.env.forum2x2` для всех не подходит. `SiteEntry` в
  `utils/site_registry.py` теперь хранит ещё и `credentials_path` —
  отдельный файл вида `.env.forum2x2_<хост>` на каждый форум, создаётся
  автоматически при первом добавлении форума (сам файл создавать нужно
  вручную — по образцу `.env.forum2x2.example`, программа только выделяет
  для него имя).
- **Ограничивать ли сканирование — теперь явный вопрос в `run_archive.py`
  и `run_forum2x2_archive.py`.** Раньше лимиты «сколько страниц/ресурсов
  скачать» относились только к скачиванию — само сканирование структуры
  форума ВСЕГДА проходило целиком, без ограничений, что на большом форуме
  может занимать часы ещё до начала скачивания, и выглядело как будто
  лимиты не действуют. Теперь перед этим прямо спрашивается: ограничить
  ли и само сканирование в этом запуске (число разделов/тем) — использует
  уже существующий и протестированный механизм `test_mode`, просто
  сделанный доступным и в боевых скриптах, не только в тестовых.

## 2026-07-24 — Отдельные папки на каждый форум на forum2x2.ru

- **Новый модуль `utils/site_registry.py`.** forum2x2.ru — общий хостинг,
  на котором может жить сколько угодно никак не связанных друг с другом
  форумов. Раньше `run_forum2x2_archive.py` был жёстко привязан к ОДНОМУ
  файлу конфигурации (`config_forum2x2.json`) и ОДНОЙ папке архива
  (`Archive_forum2x2/`) — второй форум на этом же движке перезаписал бы
  первый. Теперь при вводе нового адреса форума автоматически заводится
  свой файл конфигурации и своя папка архива (имя — на основе хоста,
  например `Archive_forum2x2_russlovo.listbb.ru/`), а список уже известных
  форумов сохраняется в `sites_forum2x2.json` и предлагается выбором из
  меню при следующем запуске. Логика реестра проверена (новый хост
  создаёт новую запись; тот же хост, даже с другим путём в URL,
  переиспользует существующую запись).
- **Не затронуто:** `.env.forum2x2` пока один общий на все форумы
  forum2x2 — если для разных форумов на этом хостинге понадобятся разные
  логин/пароль, это отдельная доработка (см. `ROADMAP.md`).

## 2026-07-23 — Уточнение входа forum2x2, активация backoff по хостам, более подробные логи

- **Признак успешного входа на forum2x2 уточнён.** Была осторожная
  эвристика («формы входа больше нет в ответе»). На реальной странице
  сразу после входа нашёлся точный признак — ссылка на выход
  `href="/login?logout=1&tid=...&key=..."` (`login_forum2x2()` в
  `network/http_client.py`, тот же принцип, что у phpBB с `mode=logout`).
- **Вложения forum2x2 — закрыто как «не требуется».** Все картинки на
  этом форуме загружаются через встроенный редактор на сторонний хостинг
  servimg.com — отдельного механизма вложений (загрузка файла как
  attachment) на форуме нет, уже покрыто обычным скачиванием картинок.
- **Backoff по отдельному хосту — обнаружен, исправлен и включён.**
  В `storage/database.py` уже существовала (но нигде не была
  подключена) логика различения «свой хост форума / чужой хост» для
  backoff — так, чтобы мёртвая или заблокированная внешняя картинка
  (например, устаревшая ссылка на radikal.ru) не приостанавливала
  скачивание всего остального, включая сам форум. По пути найдены и
  исправлены два бага:
  - `mark_task_failed()` вызывал несуществующий метод
    `_host_error_streak()` — падал с `AttributeError` при первой же
    ошибке стороннего хоста;
  - тестовый файл `tests/test_host_backoff.py` не передавал `own_host`
    при создании `QueueManager`, из-за чего проверка не могла отличить
    свой хост от чужого (плюс отдельная логическая ошибка в самом
    тесте — цикл на 3 задачи забирал все 3 существующие задачи, не
    оставляя ничего для второй части проверки).
  - Функция включена по-настоящему: во всех пяти скриптах
    `run_commands/*.py` при создании `QueueManager` теперь передаётся
    `own_host=urlparse(cfg.forum.base_url).netloc`.
- **Более подробные логи во время сканирования.** Раньше `Scanner`
  выводил в лог только итог по разделу целиком — если в разделе много
  страниц списка тем, между сообщениями могла быть долгая тишина, хотя
  работа шла (со стороны выглядело как зависание). Теперь лог пишется на
  каждой странице списка тем, с текущим счётчиком найденных тем.

## Разработка до переноса в тематические папки

- **Этапы 1–5 (форум №1, phpBB).** Конфигурация, логирование, БД;
  HTTP-клиент, вход, парсер phpBB, обход структуры (Scanner); скачивание
  текста с инкрементальной пагинацией; устойчивость к сбоям (backoff,
  возобновление, повтор попыток); скачивание ресурсов
  (картинки/вложения/аватары/CSS) и переписывание HTML на локальные пути.
- **Добавление форума №2 (forum2x2.ru).** Написан `forum2x2_parser.py` с
  тем же интерфейсом, что и у phpBB. На реальных страницах найдены и
  исправлены: неверный поиск тем (ловил виджет «последние сообщения»
  вместо реального списка — решено поиском по классу `topictitle`);
  неверный расчёт шага пагинации (номер страницы у forum2x2 — offset
  вида `posts_per_page × N`, а не 1/2/3); аватары раздаются с другого
  хоста (`7img.net`), чем обычные картинки (`servimg.com`); `Scanner`
  ошибочно считал, что главная страница форума всегда `index.php` (верно
  только для phpBB) — заменено на `HOME_PAGE_PATH` из модуля-парсера;
  реализован вход `login_forum2x2()`; добавлен заголовок `Referer` при
  скачивании ресурсов (без него сторонние фотохостинги с защитой от
  хотлинкинга отвечали 403); `credentials.py` научился читать несколько
  `.env`-файлов с разными префиксами переменных; добавлены отдельные
  боевые прогоны для каждого форума; исправлен баг с
  `ignore_errors=True`, из-за которого сообщение «начинаю с чистого
  листа» могло быть неправдой.
- **Рефакторинг структуры проекта.** Плоский список файлов разложен по
  тематическим папкам (`parsers/`, `network/`, `storage/`, `scanner/`,
  `utils/`, `tests/`, `run_commands/`), добавлена единая точка входа
  `main.py` с текстовым меню.

Подробности реализации и найденных технических находок за эти этапы —
в `README.md` (раздел «История изменений»).
